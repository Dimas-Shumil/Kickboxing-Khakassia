Федерация кикбоксинга Хакасии — удаление и сроки оплаты
13.11.2026

Что изменено
— Кнопка «Удалить» в списках и карточках учеников, групп и оплат.
— Перед удалением требуется подтверждение. При отмене ничего не меняется.
— Записи помечаются удалёнными, физически остаются в SQLite. Оплаты,
  исправления, ученики, группы, тренировки, посещения и журнал сохраняются.
— Удаление ученика не удаляет его денежные поступления. В списке оплат
  остаются имя и пометка «ученик удалён».
— Удалённая оплата исключается из сумм, аналитики и срока оплаты.
— Удалённая группа исчезает из справочника. Старые связи и названия сохраняются.
— В журнал добавляется действие удаления. Возврат удалённых записей через
  интерфейс в этот патч не входит.
— Существующее название группы остаётся зарезервированным, в том числе после
  удаления: это сохраняет привязку прежних учеников по названию.

Срок оплаты
Оплата действует один календарный месяц от фактической даты получения денег.
15 ноября -> 15 декабря. Следующая оплата 20 декабря -> 20 января.
Для 31 января срок — последний день февраля (28 или 29).
Поле «За какой месяц» остаётся для отчётов и не влияет на оплаченный срок.
Каждая сохранённая оплата считается оплатой месячного срока; частичные
платежи и пропорциональная продолжительность по сумме не рассчитываются.
Используется последняя неудалённая оплата, дата которой не позже сегодняшнего дня.
Если оплаты ещё нет, ориентиром служит начало занятий ученика.
Для статусов «Приостановил» и «Завершил» напоминания отключены.
Дата сегодня определяется по Абакану (Asia/Krasnoyarsk) при открытии раздела.

Зелёный: оплачено, до следующего срока больше трёх дней.
Жёлтый: за три дня до срока, в день срока и первые два дня после него.
Красный: с третьего дня после срока.
Пример: оплачено 15 ноября; жёлтый с 12 декабря, красный с 18 декабря.
Текущие сроки видны в разделе «Оплаты», списке и карточке ученика.
В таблице поступлений и форме оплаты показан оплаченный диапазон дат.

Миграция
202611130001_gym_soft_delete добавляет nullable deletedAt в Student, Payment,
TrainingGroup. Существующие строки не пересоздаются и не удаляются.
Сроки считаются по уже сохранённым датам получения денег: переноса дат нет.
.env, пользовательские загрузки и база в патч не включены.

Установка НА КОМПЬЮТЕРЕ ОТЦА — Windows CMD
1. Остановить npm run dev сочетанием Ctrl+C.
2. Распаковать содержимое ZIP в C:\Users\ШУМ\WORKS\kickboxing-federation
   с заменой файлов. В корне патча сразу lib, routes, prisma, site, services, tests.
3. Сделать резервную копию командой:

cd /d C:\Users\ШУМ\WORKS\kickboxing-federation
npm run db:backup

Продолжать только если выведено «Проверенная резервная копия».
Скрипт создаёт копию в backups и проверяет целостность SQLite.

4. Затем по одной команде, после успешного завершения предыдущей:

npx prisma migrate deploy
npx prisma generate
npm run dev

Нужно: резервное копирование, новая миграция, генерация Prisma Client,
перезапуск локального приложения.
Не нужно: npm ci, повторная сборка CSS (включён готовый CSS), создание владельца,
создание тренеров или распределение прежних записей.
origin и upstream не изменяются. Отправка в Git и на сервер не выполнялась.

Проверки
Автоматические: весь набор Node-тестов, включая реальные HTTP-запросы на временной
SQLite, права двух залов, CSRF, конфликт версии, суммы и исключение удалённых оплат,
сохранение строк/связей миграцией, сроки месяца/високосный год, PWA и навигация.
DOM (jsdom): кнопки, отмена и подтверждение удаления, поиск и повторная отрисовка,
сохранение одной оболочки админки без перезагрузки документа.
Prisma schema валидна; CSS собран; синтаксис изменённых JS проверен.
Браузерные: Chromium не запустился из-за ограничения среды на создание socket.
Визуальная проверка desktop/mobile и реальное поведение установленного PWA
не подтверждены. Реальная база и аккаунты на компьютере отца не проверялись.

После установки
Открыть /admin/payments, проверить даты и цвета; проверить «Удалить» и отмену
подтверждения на тестовых данных в оплатах, учениках и группах.

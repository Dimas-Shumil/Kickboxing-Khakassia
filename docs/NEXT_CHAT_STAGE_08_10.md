# ПРОМТ ДЛЯ ПРОДОЛЖЕНИЯ — Федерация кикбоксинга Хакасии, этап 08.10

Продолжаем проект Федерации кикбоксинга Республики Хакасия. Прилагаю **свежий полный ZIP после этапа 08.9**. Только этот архив считать актуальным исходником: распаковать, проверить файлы, Prisma-схему, миграции, тесты и не применять старые патчи автоматически.

Стек Node.js 24, Express ESM, Prisma 6.19.3, SQLite, HTML/SCSS/Vanilla JS, RioCar-подобные `config/lib/middleware/routes/services`. Без React и EJS. Админка OWNER/EDITOR. Публичные `/`, чистые маршруты, четыре шаблона людей и hover-фото легенды, анимации, раздельные SCSS entrypoint, favicon, кнопки radius 7px сохранять.

Подэтапы 08.4–08.8: новости, люди, соревнования, история и архив, документы, медиатека и информационные страницы. Подэтап 08.9: один зал — карточки учеников, группы, занятия, отметки посещаемости, фактические оплаты и обзор за месяц. Подробности в `docs/STAGE_08_9_GYM.md`. Приватные данные только OWNER, не доступны EDITOR, анонимным и публичному поиску. Нет долгов/просрочек/автосчёта, и не добавлять без согласования. `Student.group` — сохранённое строковое поле, совпадает с `TrainingGroup.name`, переименование запрещено. Новая миграция `202611060001_gym_attendance`, никаких изменений существующих таблиц.

**Перед следующим этапом ОБЯЗАТЕЛЬНО:** пользователь должен установить 08.9, выполнить `npm ci`, `npx prisma generate`, `npx prisma migrate deploy`, `npm test`, `npm run dev` на Node24; проверить HTTP-тесты `tests/gym-http.test.cjs` и адаптив на смартфоне. Не считать отсутствующие проверки пройденными. Исправить найденные проблемы, не меняя данные.

**Этап 08.10 — аудит и аналитика админки:** согласовать состав дашборда Федерации и зала, честные KPI на опубликованных данных; только OWNER видит финансы и частный зал. Показатели по контенту (опубликовано/черновики/архив), журнал изменений, активность редакционных работ и посещаемость зала по выбранному месяцу. Дать удобные фильтры, корректные пустые состояния и связь с источниками. Не выводить приватную информацию в публичный сайт, не создавать иллюзию долгов. Если пользователь захочет экспорт/резервные копии, сначала уточнить требования.

Не изменять пользовательские БД, загрузки, секреты; миграции только аддитивные; тесты на временных БД. Без коммитов, push, деплоя. Результат — ZIP-патч новых/изменённых файлов без `.git`, `node_modules`, `.env`, БД, пользовательских загрузок, команды CMD, отчёт реально выполненных тестов, ручной тест-план, документация и промт следующего этапа.

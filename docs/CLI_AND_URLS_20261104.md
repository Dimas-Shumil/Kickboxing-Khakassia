# Создание владельца и адреса страниц

Применять поверх 08.3, в том числе после hero-патча. Остановить сервер, скопировать содержимое архива в корень с заменой. Новых зависимостей и миграций нет.

## Создание владельца

npm run user:create

Консоль спросит имя, логин, пароль (12–256 символов) и подтверждение пароля. Ввод пароля скрыт. Создаётся OWNER. Занятый логин и несовпадающие пароли отклоняются без изменения существующего пользователя. Прервать ввод можно Ctrl+C. Затем npm run dev и вход по http://localhost:3000/admin.

ADMIN_LOGIN, ADMIN_NAME, ADMIN_ROLE, ADMIN_PASSWORD в .env для обычного создания больше не используются и могут быть удалены. DATABASE_URL и остальные настройки сервера сохраните. Существующий владелец продолжает входить без повторного создания.

Для автоматизации сохранён явный режим node prisma/create-admin.js --env (он читает переменные ADMIN_* и может сбросить пароль существующему логину). Обычная команда user:create всегда задаёт вопросы и не сбрасывает пароли. Эта инструкция заменяет прежний порядок создания через .env.

## Адреса

Главная: /
О Федерации: /federation
Новости: /news
Соревнования: /competitions
Контакты: /contacts
Другие публичные HTML-страницы также доступны по имени без расширения.

Внутренние ссылки меню, подвала, карточек, хлебных крошек и поиска обновлены. Старые /public/index.html и /index.html перенаправляются 301 на /. Другие известные страницы с /public/ или .html перенаправляются на чистый адрес. Query-параметры сохраняются; якоря передаёт браузер. Неизвестные страницы возвращают 404. Файлы физически остаются в public/, доступ к ним обеспечивает Node.js.

Запуск: npm run dev. После применения обновить страницы Ctrl+F5. Go Live для серверных маршрутов не используется.

Проверка: npm test. Дополнительно интерактивная команда проверена в псевдотерминале: создание, несовпадение паролей, занятый логин и отсутствие пароля в выводе. Базы проверок временные, пользовательская база не менялась. Коммиты, push и деплой не выполнялись.

# Этап 08.2 — рабочая админка: Express, EJS, SQLite

Первый этап перестал быть статическим прототипом. Управление запускается через Node.js по /admin. Go Live для админки больше не используется.

## Применение

Патч накопительный относительно исходного Kickboxing-Khakassia (2)(3).zip: включает интерфейс 08.1 и серверное подключение. Можно наложить и на исходный проект, и поверх предыдущего патча 08.1. Скопировать содержимое в корень проекта с заменой файлов. Не применять к другой, самостоятельно изменённой серверной версии без проверки различий.

Архив не содержит .git, node_modules, .env, базы, пользователей, паролей или данных из тестов. Старые admin-pages/dashboard.html и другие статические страницы при запуске Node перенаправляются в защищённые /admin страницы. Их HTML не раздаётся напрямую.

## Первый запуск на Windows (CMD), из корня проекта

Нужен Node.js 24.13.1 или новее в ветке 24.x. Проверка:

```cmd
node -v
npm -v
```

Затем:

```cmd
npm ci
npm run setup:local
npm run user:create
npm start
```

setup:local создаёт новую .env со случайным SESSION_SECRET и новую отдельную prisma/federation-dev.db; применяет начальную миграцию и генерирует Prisma Client. Никакие PostgreSQL или чужие базы не используются. Если .env или этот файл БД уже существует, команда останавливается, ничего не перезаписывая. Это защита, не повод удалять свою базу.

user:create спросит логин, имя и пароль. По умолчанию создаётся владелец OWNER. Пароль вводится скрыто, минимум 12 символов, не передаётся аргументом команды и не выводится. В базе хранится scrypt-хеш. Готового общего пароля в коде нет. Пользователь с занятым логином не перезаписывается.

Открыть в обычном браузере:

- сайт: http://localhost:3000
- админка: http://localhost:3000/admin

Используйте именно localhost, как в APP_ORIGIN: Origin защищает отправку форм. Не смешивайте localhost и 127.0.0.1. Для другого хоста/порта сначала измените APP_ORIGIN в .env и перезапустите приложение.

Редактор при необходимости создаётся отдельно:

```cmd
npm run user:create -- --role=EDITOR
```

На последующих запусках:

```cmd
npm start
```

Не запускать setup:local повторно для уже созданной установки. Не использовать prisma migrate reset или db push. Команды db:deploy и db:generate предусмотрены для осознанного обновления своей указанной базы; новое содержимое .env не копировать поверх существующего.

Если первый запуск остановился после создания .env, проверьте вывод ошибки. Для продолжения именно этой новой установки: npm run db:deploy, затем npm run db:generate. Не менять DATABASE_URL на неизвестную существующую базу.

## Что реально подключено

- Express 5, EJS-оболочка админки и серверные страницы входа/ошибок. Общий HTML публичного сайта сохранён.
- SQLite через Prisma 6.19.3. Версии зависимостей и lock-файл зафиксированы. Override deepmerge-ts 8.0.0 устраняет найденную транзитивную уязвимость; CLI generate, миграции и тесты проверены с ним.
- Вход/выход, постоянные сессии в SQLite, HttpOnly/SameSite cookie, CSRF-токены и проверка Origin, ограничение попыток входа, закрытые ответы no-store/noindex.
- Владелец: весь текущий функционал. Редактор: обзор сайта и новости. Сервер закрывает страницы и API учеников/финансов для редактора; bootstrap редактора не содержит контактов/оплат. Пароли/хеши не выдаются клиенту.
- Ученики: создание, изменение, статусы, стоимость, контакты и примечание, серверная валидация, сохранение в базе.
- Платежи: сумма в целых копейках, дата получения и оплаченный месяц отдельно, несколько записей за период, фильтры, сводка. Исправление требует причины; прежние значения, автор и время сохраняются сервером в той же транзакции.
- Новости: серверные черновики, редактор, сохранение, архив/возврат в черновик и закрытый предпросмотр. Черновики не выходят на публичный сайт. Для НЕсохранённой рабочей версии предпросмотр использует временный буфер вкладки, привязанный к ID вошедшего пользователя; это единственное использование sessionStorage.
- Защита от перезаписи изменений: версии учеников, платежей и новостей. При устаревшей версии сервер отвечает 409, форма остаётся с введёнными значениями.
- Серверный журнал создания/изменения. Редактор видит только события новостей.
- Корректные 404 для неизвестных страниц и записей админки, оформленная публичная 404. API возвращает JSON-ошибки с соответствующим HTTP-статусом.
- Кнопка сохранения и поля блокируются на время запроса. «Сохранено» появляется только после положительного ответа API; ошибка сети не объявляется успехом. Если соединение оборвалось после отправки платежа, проверьте список перед повторным внесением: создание платежа пока не имеет отдельного ключа идемпотентности.

Показатели новой установки нулевые. Демозаписи из предыдущего sessionStorage не импортируются. Статический публичный сайт продолжает показывать своё исходное содержимое с прежними демопометками, пока отдельный этап не подключит публикацию.

## Что ещё не реализовано

Публикация и снятие с публикации, единый источник опубликованных новостей для главной/поиска/каталога, рабочая и опубликованная версии, управление сотрудниками через UI, загрузка файлов, полноценная медиатека и зависимости, люди и публичные профили, соревнования, история, страницы и настройки остаются следующими этапами. Предпросмотр в браузере не является общедоступной ссылкой: без сессии сервер отправляет на вход. Точность публичного макета предпросмотра новости будет доведена при переносе публичного шаблона в EJS.

Привязка внутреннего ученика к публичному спортсмену ещё не подключена, её не имитирует текстовый ID. Посещаемость, расписание, PUSH, рассылки и кабинеты не добавлялись.

Начисления/долг/просрочка не рассчитываются. «Без платежей за период» означает лишь отсутствие записи, а не наличие долга. Наличие частичного платежа не означает полную оплату. Изменение текущей стоимости ученика не меняет прошлые суммы. Перед начислениями нужно согласовать общий календарный срок или индивидуальные периоды.

Публикация отключена у обеих ролей до подключения полного сценария и согласования, публикует ли редактор самостоятельно или через владельца.

## Проверка

```cmd
npm test
npm audit
```

12 проверок проходят. Они создают свои временные SQLite-файлы; пользовательская база не очищается. Проверяются сессии/выход, доступ и приватность, CSRF/Origin, серверная валидация, два платежа за период, дата получения отдельно, история/транзакции/конфликты, сохранение и перечитывание из отдельного подключения, запрет публикации, черновики/архив, HTTP 404 и защита повторной установки.

В браузере на отдельной тестовой базе проверены: форма входа, создание ученика, перечитывание после перезагрузки, внесение оплаты, создание/перечитывание новости и предпросмотр. На mobile 390×844 — рабочая оболочка без горизонтального переполнения. Настоящий логин/выход проверены HTTP-тестами; для браузерных UI-тестов использована отдельная изолированная сессия фикстуры. Тестовый вход/фикстуры/база не включены в патч.

Ручной сценарий после установки:

1. Без входа открыть /admin/students.html — перенаправление на вход.
2. Войти владельцем; новый Обзор зала пустой.
3. Добавить тестового ученика. Перезагрузить страницу — карточка на месте.
4. Внести 1 000 ₽ 27.10.2026 за 2026-11 и 500 ₽ 02.11.2026 за 2026-11. За октябрь получено 1 000 ₽, за ноябрь — 500 ₽; обе записи покрывают ноябрь. Исправить сумму с причиной и проверить историю.
5. В двух вкладках открыть одну запись: сохранить изменения в первой, затем во второй — получить конфликт версии, а не тихую перезапись.
6. Создать новость, сохранить, перезагрузить, открыть предпросмотр. Публичный сайт пока не меняется.
7. Выйти. Войти редактором: управление залом отсутствует, прямой URL даёт 403.
8. Остановить приложение Ctrl+C и запустить npm start: записи остаются.

## Хранение и эксплуатация

Локальный файл: prisma/federation-dev.db. Он содержит персональные данные, финансы и сессии; не класть его в Git и публичные каталоги. Для простой локальной резервной копии остановить приложение и скопировать БД в закрытую папку. Автоматические бэкапы и production развёртывание этим патчем не настраивались.

По умолчанию сервер слушает только 127.0.0.1. Для production нужны HTTPS, NODE_ENV=production, APP_ORIGIN с https и настройка доверенного reverse proxy; на сервер ничего не выкладывалось. Изменение SESSION_SECRET завершит действующие сессии.

Следующий небольшой этап: новости целиком — согласовать право публикации редактора, перенести публичный шаблон в EJS без изменения разметки, подключить опубликованные версии к ленте/главной/карточке/поиску и сохранить стабильные адреса.

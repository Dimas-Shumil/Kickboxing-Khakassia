# Федерация кикбоксинга Республики Хакасия — этап 08.9

## Назначение и пределы

Один зал, приватный учёт: группы, ученики, тренировки, посещаемость, фактические оплаты и месячный обзор. Вся информация в `Student`, `Payment`, `PaymentRevision`, `TrainingGroup`, `GymSession`, `AttendanceRecord` закрыта. Сайт Федерации не отображает эти записи. `OWNER` имеет полный доступ, `EDITOR` получает HTTP 403 и не видит данные в dashboard. Незалогиненный — HTTP 401 для API и редирект на `/admin/login` для страниц.

**Запрещённые и не реализованные допущения:** долги, начисления, просрочки, задолженность за период, автосчета, несколько залов. `Payment.period` — месяц, к которому владелец отнёс уже полученный платёж; он **не создаёт обязательство**. Обзор показывает сумму по `Payment.received` и число фактических поступлений. Статус «отсутствовал» означает только посещаемость, не оплату.

## Модель данных

- Сохранены старые `Student.group` (произвольный текст), `Payment`, версии, ревизии и история. Миграция не обновляет эти таблицы.
- `TrainingGroup` — уникальное неизменяемое после создания название, тренер, описание, статус `active/archived`, версия. Для привязки ученика укажите в карточке **точно то же название** группы. Если ранее у ученика было свободное название, оно сохранится до изменения владельцем. Переименование запрещено во избежание автоматического изменения старых данных; можно создать новую группу и переназначить карточки.
- `GymSession` — дата `heldOn` (красноярское календарное число), время начала/конца в пределах дня (`HH:mm`), название, тренер, группа (необязательна), статус `planned/held/cancelled`, версия, примечание. Группа в архиве не принимает новые занятия; старые сохраняются.
- `AttendanceRecord` — отметка ученика для тренировки, статус `present/absent/excused`, заметка, уникальность `(sessionId,studentId)`. Неотмеченный ученик **не считается отсутствующим**. Снятие отметки отправляется явно (`status:""`). Для сохранения требуется `GymSession.status === "held"`. Если есть отметки, отменить тренировку или сменить группу/снять статус `held` нельзя до явного снятия отметок.
- Существующие таблицы и записи не пересоздаются. Добавлена `prisma/migrations/202611060001_gym_attendance/migration.sql`: только три новые таблицы и индексы.

## API (все запросы только OWNER)

`GET /api/admin/gym/summary?month=YYYY-MM` — статистика фактических тренировок, отметок и поступлений по выбранному месяцу.

`GET /api/admin/gym/groups`, `GET /api/admin/gym/groups/:id`, `POST /api/admin/gym/groups`, `PATCH /api/admin/gym/groups/:id` — справочник групп.

`GET /api/admin/gym/sessions?month=YYYY-MM`, `GET /api/admin/gym/sessions/:id`, `POST /api/admin/gym/sessions`, `PATCH /api/admin/gym/sessions/:id` — тренировки.

`PATCH /api/admin/gym/sessions/:id/attendance` — пакет отмеченных учеников `{version,marks:[{studentId,status,note}]}`. Не переданные ученики не изменяются. Не больше **250** отметок за один запрос. Для новой отметки групповой тренировки студент должен иметь совпадающее название группы (старые уже сохранённые отметки можно корректировать после смены группы). Для общей тренировки без группы разрешены любые существующие ученики.

`GET /api/admin/gym/students/:id/attendance` — посещения ученика, только OWNER.

POST/PATCH требуют текущую сессию, Origin и CSRF-токен, серверную валидацию полей. PATCH также требует `version`; старая версия — HTTP 409 с сохранением введённых данных **в браузерной форме**. Ошибки данных — HTTP 422; неизвестные ID — HTTP 404. Изменения данных и AuditLog выполняются в одной транзакции.

## Экраны

`/admin/gym` — фактический отчёт за выбранный месяц, тренировки, поступления, переходы.

`/admin/students`, `/admin/student?id=...` — ученики, группа, история оплат и история посещений.

`/admin/groups`, `/admin/group?id=...` — справочник групп, численность, архивирование.

`/admin/trainings?month=YYYY-MM`, `/admin/training?id=...` — календарь месяца, поиск, фильтры, создание и редактирование занятия.

`/admin/attendance?id=...` — отметки посещения, примечания, явно пустое состояние.

`/admin/payments`, `/admin/payment?id=...` — существующий учёт фактически полученных оплат без изменения бизнес-логики.

Стили только в `site/sass/admin.scss` и готовых `site/css/admin.css`, `site/css/admin.min.css`, с радиусом кнопок 7px. Публичные SCSS и четыре шаблона людей не затронуты.

## Безопасный запуск на своём ПК (Windows CMD)

В каталоге проекта после применения ZIP и предварительного резервирования **своей** базы:

```cmd
npm ci
npx prisma generate
npx prisma migrate deploy
npm test
npm run dev
```

Новые владельцы/редакторы не нужны, если они уже созданы.

## Тесты и приёмка

- `node --test tests/gym.test.cjs` — изолированные проверки валидации, версий 409, отмены занятий, исключения двойных отметок и сводки.
- `tests/gym-http.test.cjs` — полноценные HTTP/Prisma/Express проверки, на **временной SQLite**; должны пройти на Node.js 24 вместе с `npm test`.
- Миграция протестирована на отдельной SQLite с выполнением всех восьми SQL-миграций; старые записи ученика и оплаты сохранены, `PRAGMA integrity_check=ok`, ошибок FK нет.
- Ручной сценарий: зал пустой → группа → ученик с такой группой → тренировка `planned` → перевести в `held` → отметить посещение → открыть ученика → изменить отметку и конфликт с двумя вкладками → проверить месячный отчёт → оплатить по факту → проверить редактора и гостя → архив группы → проверить 404 и мобильный экран.
- **Ограничение:** проверка с реальными зависимостями и тестирование в браузере не проводились в среде разработки (Node 22, npm не завершил установку); обязательно запустить `npm test` на Node 24.

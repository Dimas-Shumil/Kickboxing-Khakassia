Продолжаем сайт Федерации кикбоксинга Республики Хакасия. Прикрепляю свежий ZIP — единственный актуальный источник кода. Сначала распакуй, изучи структуру, документацию и тесты. Не накладывай старые патчи автоматически.

Текущая основа: Node.js 24.x, Express, ES-модули, Prisma 6.19.3, SQLite; HTML/SCSS/Vanilla JS без React. Архитектура по образцу RioCar: config, lib, middleware, routes, services; HTML админки в admin-pages, клиентский JS в site/scripts/admin. Владелец создаётся через npm run user:create: имя, логин, скрытый пароль, подтверждение. Запуск npm run dev. Главная /, публичные разделы без /public и .html; старые адреса перенаправляются.

Уже подключены вход/выход, OWNER/EDITOR, SQLite-сессии, CSRF/Origin, heartbeat; ученики одного зала, платежи, история исправлений, контроль версий; черновики новостей и закрытый предпросмотр. Публичные новости пока используют демонстрационные источники. Проверь всё по архиву.

Следующий этап 08.4 — законченные новости: создание → сохранение → предпросмотр → публикация → обновление сайта и поиска → снятие с публикации/архив → восстановление.

Сделай серверное хранение рабочей и опубликованной версий отдельно: сохранение правок не должно менять опубликованный материал до явной публикации. Стабильная индивидуальная ссылка, серверная валидация, безопасный вывод текста, защита от перезаписи чужих изменений. Неопубликованные новости и предпросмотр не должны быть доступны анонимно; неизвестный или снятый материал возвращает HTTP 404. По возможности сохранить ссылки существующих материалов.

Подключи новости из SQLite к ленте /news, странице публикации, блоку главной и общему поиску. Один источник опубликованных данных. Обработай загрузку, ошибку и пустой каталог. Не смешивай демоматериалы с реальными публикациями и не выдавай их за реальные. Продумай переход с текущих демонстрационных JS-данных без потери вёрстки.

Добавь загрузку обложки и фотографий галереи через админку: ограничения размера и типа, безопасные имена файлов, защита от удаления используемых изображений; подписи, alt и авторство.

До реализации прав публикации задай один вопрос: редактор публикует самостоятельно или только готовит материалы для владельца? Это ранее не согласовано. Пока ожидаешь ответ, изучай код и делай независимую часть работы.

Сохрани дизайн, анимации, фото-hero, радиус кнопок 7px, favicon с логотипом, отсутствие декоративных стрелок и чистые URL. Каждая публичная страница имеет собственный SCSS entrypoint; уникальные стили остаются в нём, общие повторяемые компоненты можно подключать через @use; не импортировать main.scss в другие страницы. Семантика header/main/section/footer.

Ученики, контакты родителей и финансы приватны. Редактор к ним не допускается. Учёт зала только одного, без филиалов. Дата платежа и оплачиваемый месяц отдельно, несколько платежей за период допустимы. Начисления, задолженность и просрочку не добавлять: порядок оплаты не согласован.

Проверить права, публикацию/снятие, сохранность опубликованной версии при правках, конфликты, загрузку файлов, XSS, публичные 404 и отсутствие черновиков/приватных данных в поиске. Проверить интерфейс на компьютере и мобильном экране; явно сообщить, что не удалось проверить.

Работай небольшим законченным этапом. Выдай ZIP только с новыми/изменёнными файлами, без .git, node_modules, .env и баз, инструкцию применения и запуска, сценарий проверки, что работает и что осталось. Миграции подготовь, но существующие пользовательские базы не меняй. Коммиты, push и деплой не выполняй.

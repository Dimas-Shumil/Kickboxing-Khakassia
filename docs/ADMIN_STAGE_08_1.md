## Как применить и открыть

1. Сделать обычную резервную копию папки проекта.
2. Распаковать ZIP-патч и скопировать его содержимое в корень существующего проекта, рядом с package.json. Согласиться на замену admin-pages/dashboard.html и admin-pages/news.html — в исходнике они пустые.
3. Открыть корень проекта в VS Code (не только папку public).
4. Открыть admin-pages/dashboard.html через Open with Live Server / Go Live.
5. Обзор зала: admin-pages/gym.html. Все экраны связаны навигацией.

Для этого этапа npm install, сервер, БД, .env и миграции не нужны. Не открывать через file://. Исходный npm start по-прежнему раздаёт публичный сайт; маршрута админки в нём пока нет. Патч не предназначен для выкладки как защищённая рабочая админка.

CSS уже скомпилирован. Только если меняете SCSS, из корня проекта:

```bash
npm install
npx sass site/sass/admin.scss site/css/admin.css --no-source-map --style=expanded
npx sass site/sass/admin.scss site/css/admin.min.css --no-source-map --style=compressed
```

Это существующая зависимость Sass, дополнительных зависимостей патч не требует. admin.scss независим: использует только base/variables, не импортирует main.scss, публичные header/footer или базовые глобальные правила. Иконки Bootstrap Icons поставляются локально, лицензия рядом. Логотип — исходный logo-fed.png на белой подложке для читаемости на тёмном фоне; знак из сгенерированного макета не используется.

## Реально работает на уровне интерфейса

- Девять страниц с общей оболочкой: обзор сайта, обзор зала, ученики, карточка ученика, оплаты, форма оплаты, новости, редактор и предпросмотр.
- Сворачиваемое мобильное меню; фокус внутри открытого меню, Escape, видимые подписи/фокус. На узком экране таблицы становятся списками с подписями полей.
- Демозаписи учеников: создание, изменение, статус, стоимость, контактные поля, примечание, временный ID связи с публичным профилем, история платежей.
- Фактические платежи: ученик, сумма, дата получения, оплаченный месяц, комментарий. Несколько записей за один месяц допустимы. Суммы хранятся в целых копейках.
- Исправление платежа требует причины и сохраняет предыдущие значения, включая ученика, сумму, дату, период и комментарий, во временной истории.
- Обзор пересчитывается из записей, без зашитых показателей макета. Получено за месяц — по дате поступления. «Без платежей за период» — действующие ученики без единого платежа за этот месяц; это не долг и не признак полной оплаты.
- Поиск/фильтры учеников, платежей, новостей; пустые результаты и отсутствующая запись по ID.
- Новости инициализируются из существующего FED_NEWS. Изменения — отдельные черновики во вкладке. Создание, редактирование, архив/возврат в черновик, обложка из проекта, подписи, авторство/источник, галерея из доступных изображений, предпросмотр и возврат без потери текста.
- Текст новости выводится как текст, HTML не исполняется. Публикация недоступна.
- Проверка обязательных полей средствами браузера и дополнительные проверки имени, суммы/ученика, текста. Ошибки записи в sessionStorage показываются без ложного сообщения о сохранении.
- Предупреждение об уходе с изменённой формы, сброс с подтверждением, временный журнал действий.

## Ограничения первого этапа

Все люди и суммы здесь демонстрационные. Не вводить реальные персональные данные. Запись только в sessionStorage текущей вкладки, без отправки на сервер; она не является надёжным хранением и может исчезнуть при закрытии вкладки. Функции импорта/экспорта реальных данных не подключены. В приватном режиме/при запрете хранилища сохранение может быть недоступно; ошибка видна в интерфейсе.

Нет авторизации, серверной проверки прав и валидации, постоянного сохранения, серверной истории, защиты от конкурентных правок, реальной привязки публичного профиля, загрузки файлов, сортировки галерей, категорий как справочника, связанных материалов, публичной публикации, закрытого серверного предпросмотра. Неизвестный ID отображает локальное состояние «Запись не найдена», но это не серверный HTTP 404. Прямые адреса статического прототипа не защищены. Не вводить реальные данные и не размещать их в HTML/JS.

Остальные разделы показаны как «Позже», без пустых ссылок. Посещаемость, расписание, PUSH, рассылки, кабинеты, филиалы не реализуются.

## Проверяемый сценарий

1. Открыть Обзор сайта. Счётчики отражают только демоматериалы; посещаемость не придумана.
2. В Обзоре зала выбрать ноябрь 2026. В исходных примерах: 3 действующих ученика, 1 500 ₽ получено в ноябре, 1 ученик без платежа за ноябрь.
3. Выбрать октябрь 2026: 3 000 ₽ поступлений; платёж 27 октября за ноябрь относится к октябрьскому поступлению.
4. Добавить «Тестовый ученик · демо», стоимость 3 500. Открыть карточку из списка. Изменить статус/стоимость. Отфильтровать список; запрос без совпадений даёт пустое состояние.
5. Из карточки внести 1 000 ₽ 27.10.2026 за 2026-11 и второй платёж 500 ₽ за тот же месяц. В октябрьской сводке прибавится 1 500 ₽; в ноябрьской сумма поступлений от этого не изменится, а отсутствие платежей исчезнет.
6. Изменить первый платёж на 1 200 ₽ с причиной. Открыть повторно: прежние 1 000 ₽ и причина видны в истории. Изменение стоимости занятий не меняет платежи.
7. Попробовать нулевую/отрицательную сумму и пустую форму. Запись не должна добавиться.
8. Создать новость, заполнить заголовок/анонс/текст, выбрать обложку, добавить фотографию. Предпросмотр → вернуться: поля сохранены. Сохранить во вкладке → найти в списке. Архивировать и вернуть в черновик.
9. Изменить текст и перейти в другой раздел: появится предупреждение. Публикация недоступна, публичный сайт не меняется.
10. Уменьшить окно до 390 px: открыть/закрыть меню, проверить таблицы и формы без прокрутки всей страницы по горизонтали. Сбросить демоданные и проверить исходные примеры.

Проверка здесь: браузер Chrome, настольный viewport 1363×936 и мобильная область iframe 390×844 (адаптивная вёрстка; физический телефон и Safari не проверялись). Проверены создание ученика, раздельные дата/период, исправление платежа и история, предпросмотр/возврат/сохранение новости, предупреждение об уходе. Подробная визуальная проверка — design-qa.md. Сбой хранилища обработан кодом; принудительное исчерпание квоты не проверялось.

## Дальнейшая интеграция — SQLite

Выбор SQLite заменяет PostgreSQL в исходном плане. Для одного зала и начального объёма это подходит: локальная файловая база с транзакциями и ограничениями. Node/Express, EJS и Prisma подходят к существующему проекту; фронтенд переписывать на React/Vue не требуется. При нескольких процессах записи/росте нагрузки нужно отдельно проверить блокировки и стратегию перехода на серверную СУБД.

Следующий небольшой этап: Express/EJS + Prisma с provider sqlite, отдельная новая база разработки, владелец/редактор, вход/выход и серверная защита маршрутов. На этом этапе подготовить .env.example с отдельным путём БД и точные проверенные команды установки/создания базы для Windows. Существующие базы не трогать, production базу не создавать автоматически. Перед добавлением миграций зафиксировать версии Node/Prisma, расположение БД и правила резервного копирования.

Потом новости целиком: рабочая/опубликованная версии, стабильные slug, оптимистичная блокировка правок, серверный предпросмотр и HTTP 404, общая выборка для главной/ленты/карточки/поиска. Сохранить существующие /public ссылки либо добавить совместимые перенаправления, EJS переносить по одному шаблону. Демоматериалы не публиковать автоматически.

Затем ученики/фактические платежи с серверным журналом и раздельными публичными/внутренними DTO. Деньги — целые копейки, оплачиваемый месяц отдельно от даты поступления; стоимость прошлых периодов фиксировать, когда появятся начисления. Никаких сроков оплаты и просрочек до согласования.

После этого люди (единая запись с независимыми признаками), соревнования, история с точностью дат, медиатека/документы, страницы и настройки.

Два решения остаются открытыми и не блокируют интерфейс: порядок оплаты (общий календарный срок или индивидуальные периоды) и право редактора самостоятельно публиковать. Уточнять непосредственно перед реализацией соответствующих серверных правил. Владелец имеет полный доступ, редактор — только публичное содержимое, без учеников/финансов/сотрудников.

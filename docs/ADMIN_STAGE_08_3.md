# Этап 08.3 — архитектура по образцу RioCar

Node.js 24.x (от 24.13.1), Express, ES-модули, Prisma 6.19.3, SQLite.

## Структура

- server.js — запуск, соединение с базой и завершение процесса.
- config/ — окружение и параметры сессий.
- lib/ — Prisma, сборка приложения, HTTP и валидация.
- routes/ — маршруты /admin и /api/admin/… по разделам.
- middleware/ — авторизация, роль владельца, Origin и CSRF.
- services/ — сессии, пароли, операции с записями.
- admin-pages/ — HTML админки.
- site/scripts/admin/ — клиентская логика и контроль сессии.
- prisma/ — схема, миграции, create-admin.js.

## Применение поверх 08.2

Остановите сервер Ctrl+C. Сохраните резервную копию .env и SQLite-файла по DATABASE_URL (относительный file:./… разрешается от prisma/). Базу копируйте при остановленном сервере.
Распакуйте патч в корень проекта с заменой файлов. Существующий .env сохраните.

```cmd
npm install
npx prisma generate
npx prisma migrate deploy
node tools/cleanup-legacy.cjs
npm run dev
```

Очистка удаляет только известные устаревшие файлы 08.2 с совпадающей контрольной суммой. Изменённые вручную файлы сохраняются с сообщением. .env и базы очистка не затрагивает. Старые setup:local и user:create заменены штатными командами Prisma и create-admin.js.

Миграция сохраняет учеников, оплаты, историю и черновики. Существующие владельцы продолжают входить; при первом правильном входе старый scrypt-хеш переводится в Argon2id. Повторно создавать владельца при обновлении не требуется. Старые сессии потребуют нового входа.

Проверьте APP_ORIGIN в .env: для локальной работы допустимо
APP_ORIGIN=http://localhost:3000,http://127.0.0.1:3000

## Чистая установка

```cmd
copy .env.example .env
npm install
npx prisma generate
npx prisma migrate deploy
```

Откройте .env локально и заполните ADMIN_LOGIN, ADMIN_PASSWORD (12–256 символов), ADMIN_NAME и ADMIN_ROLE=OWNER своими значениями. Затем:

```cmd
node prisma/create-admin.js
npm run dev
```

После создания удалите ADMIN_PASSWORD из .env. Он нужен только команде создания/сброса пароля. Повторный запуск create-admin.js для того же логина обновляет пароль и отзывает его сессии; роль существующего пользователя не меняется.

Сайт: http://localhost:3000
Админка: http://localhost:3000/admin
Обычный запуск: npm run dev или npm start, как в RioCar.

## Что работает

Вход и выход, OWNER/EDITOR, SQLite-сессии, CSRF/Origin, heartbeat, ученики, несколько платежей за один месяц, история исправлений, проверка версий записей, черновики новостей и закрытый предпросмотр. Редактор не имеет доступа к финансам и ученикам. Сессия: до 4 часов, простой 2 минуты; открытая страница обновляет её heartbeat каждые 30 секунд.

Публикация новостей пока отключена. Публичные каталоги используют прежние источники. Начисления, долги и просрочка не рассчитываются. Остальные разделы админки остаются запланированными.

## Проверка

```cmd
npm test
```

Тесты создают отдельные временные базы. Проверяются права, CSRF, Origin, сохранение, несколько платежей, история, конфликты, черновики, 404, отзыв/истечение сессий и обновление 08.2 со старым паролем.

Вручную: войти владельцем → добавить ученика → внести два платежа за один месяц → обновить страницу → исправить платёж с причиной → проверить историю. Войти редактором → проверить запрет /admin/students → сохранить черновик новости и открыть предпросмотр. Неизвестный публичный адрес должен возвращать HTTP 404.

Архив не содержит .env, баз, node_modules или .git. Коммиты, push и деплой не выполнялись. Следующий этап: согласовать право редактора на публикацию и подключить новости к публичному сайту и поиску.

# Этап 08.10 — аналитика Федерации и одного зала

Исходник: полный ZIP `Kickboxing-Khakassia — копия(3).zip` с применённым патчем 08.9. Старые пользовательские SQLite, медиа, секреты не изменяются. **Новых Prisma-моделей и миграций нет**: источники существующие `AuditLog`, `News`, `Person`, `Competition`, `HistoryMaterial`, `SitePage`, `FederationDocument`, `Student`, `Payment`, `TrainingGroup`, `GymSession`, `AttendanceRecord`.

## Доступ и приватность

- `GET /api/admin/analytics/overview?month=YYYY-MM`: любая активная админ-сессия. `EDITOR` видит ТОЛЬКО редакционные показатели и активность по `news`, `people`, `competitions`, `history`, `site-page`, `site-document`, `site-media`. Таблицы учеников/оплат/посещений **вообще не запрашиваются** для редактора.
- `OWNER` получает дополнительно **приватный** объект `gym`. Нет публичных API аналитики, анонимные HTTP-запросы получают 401.
- `GET /api/admin/analytics/activity?month=YYYY-MM&scope=all&action=all&page=0`: журнал по одному месяцу с фильтрами, сортировкой по времени (новые первыми), 20 на страницу, лимит 101 страница (если записей больше 2020, фильтруйте по месяцу/разделу/действию). Попытка запроса приватного раздела от `EDITOR` — HTTP 403; неизвестный раздел или некорректные параметры — 422.
- `/admin/dashboard`, `/admin/activity` доступны владельцу и редактору после входа. Редактор не получает даже агрегированные данные зала.
- Данные не отправляются в публичный поиск, не размещаются в клиентском HTML заранее. Административный API имеет `Cache-Control: no-store`.

## Формулы и честная интерпретация

### Контент на момент запроса

- **Опубликовано**: `status==='published'` и `publishedPayload!=null` (для страниц — `publishedPayload!=null`, поскольку `SitePage` без status). Рабочие правки не меняют показатель.
- **Без публикации**: запись без действующего опубликованного снимка и не в архиве.
- **В архиве**: статус `archived`.
- **Ожидают обновления**: есть текущий опубликованный снимок, при этом `payload !== publishedPayload`. Эти материалы **не считаются дважды** в сумме публикаций.
- По страницам считаются только созданные в SQLite записи из трёх страниц; ещё не созданный шаблон не превращается в публикацию или черновик.

### Редакционная активность

`AuditLog` за выбранный календарный месяц по Хакасии (Asia/Krasnoyarsk, UTC+7): фильтрация `createdAt >= местная полуночь начала месяца` и `createdAt < местная полуночь следующего месяца`. Считаются **события**, а не уникальные изменённые записи или просмотры. Сведения о прошлых версиях/старых полях, которых нет в AuditLog, не восстанавливаются. В журнале есть дата, раздел, действие, отображаемое имя сотрудника, ссылка на редактор соответствующей записи. У удалённых сотрудников показывается «Удалённый сотрудник». Удалённые материалы могут вести на честный 404. Финансы и журнал зала видит только OWNER.

### Зал (только OWNER)

- Активные ученики/группы: текущий `status==='active'`, без исторической ретроспективы.
- Занятия: месяц по `GymSession.heldOn`, статусы `planned / held / cancelled`.
- Посещения: считаются только **сохранённые отметки** проведённых занятий; `present`, `absent`, `excused` показаны раздельно. Ученик без отметки **не считается отсутствующим**.
- Поступления: `Payment.amount` в копейках по дате **фактического получения** `Payment.received`, месяц `Payment.period` *не участвует* в расчёте. Диаграммы разбиты по календарным дням `1–7, 8–14, 15–21, 22–28, 29–последний день`.
- Нет долгов, просрочек, нормативов оплаты, новых счетов, «собрать должны», автоматических начислений и второго зала.

## Изменённые экраны

- `/admin/dashboard?month=2026-11`: KPI действующих публикаций, черновиков и ожидающих подтверждения правок; карточки по каждому разделу; журнал за месяц; для OWNER — фактически полученные поступления и отмеченные присутствия по неделям, переход на обзор одного зала.
- `/admin/activity?month=2026-11`: журнал с фильтрами месяц/раздел/тип действия, пагинацией, ссылками на административные формы. На смартфонах используется существующая responsive-table и мобильная боковая навигация.
- Добавлен пункт «Журнал действий» в боковую панель; «Обзор» переименован в «Аналитика». Чистые URL и существующие шаблоны сайта не тронуты.

## Проверки и границы результата

Изолированные тесты `tests/analytics.test.cjs` проверяют разграничение ролей (включая запрет чтения приватных таблиц редактором), состояния публикаций, границы месяцев по Хакасии, подсчёт присутствий/платежей по неделям, валидацию и журнал. `tests/analytics-http.test.cjs` содержит интеграционный сценарий на временной SQLite с владельцем и редактором. Все существующие серверные тесты должны быть запущены пользователем на Node 24 после `npm ci`/`prisma generate`/`migrate deploy`.

## Запуск Windows CMD

Остановить сервер. Сохранить резервную копию существующей БД и пользовательских загрузок. Применить ZIP-патч 08.10 **поверх полной версии с установленным 08.9**. Затем:

```cmd
npm ci
npx prisma generate
npx prisma migrate deploy
npm test
npm run dev
```

Отдельной миграции 08.10 нет; `migrate deploy` безопасно перепроверяет применённые миграции. Коммиты, push, деплой не проводились.

## Ручная приёмка

1. Сначала проверить прохождение `npm test`, включая 08.9 HTTP и 08.10 HTTP. Открыть `/admin/dashboard` и `/admin/activity` под владельцем; выбрать месяцы с событиями и без, проверить подписи и переходы.
2. Создать тестовую новость редактором (черновик), сохранить; в дашборде возрастёт счётчик «без публикации». Опубликовать владельцем — возрастёт «опубликовано». Сохранить новые рабочие правки — возрастёт «ожидают обновления», публичная публикация останется неизменной.
3. Выбрать месяц журнала. Отфильтровать `news`/`publish`, перейти по записи; проверить сортировку по времени, действие, имя. Проверить пустой месяц и повторный запрос после сбоя сети.
4. Под OWNER создать проведённую тренировку и поставить присутствие; проверить число присутствий и подпись недели. Удаление отметки должно уменьшить число. Создать реальную оплату с `received` в текущем месяце и `period` в предыдущем: сумма должна попасть именно в месяц `received`.
5. Под EDITOR проверить отсутствие карточек зала, отсутствие приватных разделов в фильтре; прямые `/api/admin/analytics/activity?month=2026-11&scope=payments` и `...scope=students` должны вернуть 403, в обзорном JSON не должно быть `gym` и сведений об учениках.
6. Без входа `GET /api/admin/analytics/overview`, `/api/admin/analytics/activity` должны вернуть 401, `/admin/activity` переводит на вход. В публичных страницах и поиске нет новых данных.
7. На мобильном экране (375px) проверить карточки, пятистрочные подписи недель, таблицу журнала, фильтры, переключение месяцев и работу меню. Проверить SCSS-компиляцию через `npm run build:admin`, при этом стиль и кнопки 7px не меняются.

## Не сделано

Полный browser/HTTP тест и компиляция Sass в локальной среде сборки не подтверждены (Node 22 вместо требуемого Node 24, отсутствующие установленные зависимости). Журнал фиксирует доступные события действий, а не изменённые «до/после» поля. Экспорт, резервные копии, мониторинг посетителей и SEO остаются отдельными решениями/этапами.
